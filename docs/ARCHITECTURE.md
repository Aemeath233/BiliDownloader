# 源码结构与运行流程

## 分层

| 目录 | 负责内容 |
| --- | --- |
| `bili_client/core` | 数据模型、文件名、错误提示、URL 与日志安全边界 |
| `bili_client/services` | HTTP、B 站接口、登录、任务调度、文件存储、限速、FFmpeg |
| `bili_client/ui` | 页面、组件、动画、主线程回调分发 |
| `scripts` | 开发者构建和单文件验证工具，不是程序运行依赖 |
| `tests` | 纯逻辑、网络边界、账号并发、下载恢复与 Tk 界面回归测试 |

## 启动

`main.py` → 单实例检查 → 显示窗口框架 → 后台初始化证书、配置、账号和任务记录 → 主线程构建默认页。队列、设置、日志页第一次访问时创建，后续复用。

后台线程只执行 I/O 或计算，再将回调放入窗口共享队列。Tk 控件始终在主线程操作。回调分发限制单轮数量和执行预算；单个回调仍应保持短小。

## 下载

解析链接与画质 → 创建任务 → 调度器限制并发 → 获取签名媒体地址 → 分别下载视频和音频 → FFmpeg 以 `-c copy` 封装 → 原子替换输出文件。

备用地址重试覆盖当前流的临时文件，并重置该流的字节统计；另一条流的进度保留。已知长度不一致或空媒体流不能作为成功下载。失败与取消的任务可以重新加入队列，当前重试会从头下载。

## 状态与锁

- `DownloadManager` 分别保护运行设置与任务状态，写记录发生在任务状态转换时，不在每个下载块都写磁盘。
- `AuthService` 用独立锁串行网络刷新，本地缓存锁只保护账号读写；设置页读取账号不会等待登录网络请求。
- 刷新结果写回时核对账号身份，避免旧请求覆盖新扫码或手工更新的账号。
- UI 回调根据请求标记判断是否过期，快速切页、切换分集和清空选择不会被旧结果覆盖。

## 前端性能

- 一个窗口共享一个动画调度器，无动画时不安排动画帧。
- 页面切换移动现有整页，不逐帧重建控件；导航按方向过渡。
- 每页最多 30 张任务卡片，分批创建，字段没有变化时不重新配置。
- 分集选择只为当前页建立 Tk 变量，其他选择保存在 Python 状态中。
- 隐藏日志页不重画文本；筛选输入防抖，新增匹配日志增量插入。
- 空闲及最小化窗口降低状态刷新频率，下载过程中仍保持后台任务运行。

## 安全边界

用户提供的视频 URL 只接受 `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 和 `b23.tv` 的支持形式；短链重定向也受域名约束。账户 Cookie 仅发送至 B 站域名，不发送给媒体 CDN。网络请求必须使用 HTTPS；账户 POST 的跨站重定向被阻止。

Windows 登录信息以当前用户 DPAPI 保护。任务记录不保存 SESSDATA，日志会隐藏常见账号令牌。HTTPS 使用系统证书与 certifi，并保留主机名和证书链校验。

源码版的 FFmpeg 默认只检查 PATH 中的绝对目录；可以在设置中指定可执行文件。打包程序只检查自身资源中的固定路径，不扫描磁盘。
