# 源码结构与运行流程

## 分层

| 目录 | 负责内容 |
| --- | --- |
| `bili_client/core` | 数据模型、文件名、错误提示、URL 与日志安全边界 |
| `bili_client/services` | HTTP、B 站接口、登录、任务调度、文件存储、限速、FFmpeg |
| `bili_client/desktop` | WebView2 窗口、本地通信桥、服务生命周期与内嵌前端资源 |
| `bili_client/ui` | 旧 Tk 界面，保留历史回归用例；新入口与发行包不加载它 |
| `scripts` | 开发者构建和单文件验证工具，不是程序运行依赖 |
| `tests` | 纯逻辑、网络边界、账号并发、下载恢复、桌面通信桥与旧 Tk 回归测试 |

## 启动

`main.py` → 单实例检查 → `desktop/window.py` 创建 WebView2 窗口 → 内存加载 HTML/CSS/JavaScript → 后台初始化证书、配置、账号和任务记录 → 前端取得就绪快照。四个页面在同一个文档中切换，不创建新窗口，也不请求页面资源。

前端资源随 Python 包分发并组装为内存文档，不启用 HTTP 服务器，不加载 CDN。通过 `window.pywebview.api.invoke(command, payload)` 调用显式白名单命令，pywebview 在工作线程执行 Python 方法，以 Promise 返回 JSON 结果。DOM 更新仅在浏览器线程执行；页面切换不依赖 Python 响应。

`DesktopRuntime` 负责服务初始化、日志序号、配置与账号版本、退出清理。`DesktopBridge` 负责参数验证、解析结果 ID、账号隔离的短期画质缓存、下载任务构造和原生文件对话框。Cookie、SESSDATA 与账号文件不随状态快照发给前端；手工输入凭证只向 Python 单向更新。旧配置、DPAPI 登录信息和任务记录继续兼容。

## 下载

解析链接与画质 → 创建任务 → 调度器限制并发 → 获取签名媒体地址 → 分别下载视频和音频 → FFmpeg 以 `-c copy` 封装 → 原子替换输出文件。

备用地址重试覆盖当前流的临时文件，并重置该流的字节统计；另一条流的进度保留。已知长度不一致或空媒体流不能作为成功下载。失败与取消的任务可以重新加入队列，当前重试会从头下载。

## 状态与锁

- `DownloadManager` 分别保护运行设置与任务状态，状态转换仅请求保存，`TaskWriter` 合并短时间内的请求并顺序落盘。任务锁内复制状态，排序、JSON 编码与 fsync 在锁外执行；正常退出等待最后的保存版本，失败保留明确提示。
- `AuthService` 用独立锁串行网络刷新，本地缓存锁只保护账号读写；设置页读取账号不会等待登录网络请求。
- 刷新结果写回时核对账号身份，避免旧请求覆盖新扫码或手工更新的账号。
- UI 回调根据请求标记判断是否过期，快速切页、切换分集和清空选择不会被旧结果覆盖。
- 画质读取最多一个请求在运行，防抖后仅保留最后一个待处理选择；手动刷新会使当前分集的 UI 和取流缓存失效。

## 前端性能

- 切页仅切换已有页面，180ms 的短距离 transform/opacity 过渡由 WebView2 渲染；尊重系统减少动态效果偏好和应用动画开关。
- 队列每页最多 30 行 DOM，以 task_id 复用节点；轮询只更新变化字段，不重建整页或打断选择与焦点。
- 分集每页最多 12 行 DOM，选择状态保存在 Set，跨页保留。
- 画质读取最多一个请求在运行，防抖并只处理最后一个待处理选择；解析和画质请求以代号拒绝过期结果。
- 状态轮询最多一条在途请求，正常每秒、隐藏时每三秒；仅在队列页获取完整任务快照。
- 前端只保留最近 1000 行日志；日志页隐藏时不更新文本，后端按序号分批交付日志，最多保留 5000 行。
- 设置未保存时不被轮询刷新覆盖。次要选项按需展开；下载页解析成功后压缩输入区，给分集和下载按钮留出空间。

## 安装与运行

主交付使用 Inno Setup 包装 PyInstaller 文件夹构建：用户安装时展开一次，之后从安装目录直接加载 Python 和前端资源，不再每次启动解包。包内为约 2.2 MiB 的专用静态 FFmpeg，保留相关解封装、音频探测和 MP4 无损封装能力，不带转码编码器。已有系统 WebView2 时复用；缺少时由安装向导提示并联网安装微软 Evergreen 共享运行时。卸载保留用户设置、账号、下载记录和视频，不移除共享运行时。

标准发行包包含 Python、前端资源、pywebview/.NET 互操作 DLL 和 FFmpeg，使用系统 WebView2。完整包再包含微软签名的 x64 Fixed Version WebView2，通过 `WEBVIEW2_RUNTIME_PATH` 直接运行包内版本。单文件包释放到 PyInstaller 临时目录；文件夹包无需每次解包。两者均不安装浏览器运行时。配置与账号继续保存在 `%APPDATA%/BiliDownloader`，不是跟随 EXE 迁移账号的沙盒模式。

关闭时有未完成下载会在内嵌界面中提供停止退出、最小化继续和取消三种选择；正常退出等待下载管理器停止并落盘，再关闭 HTTP 连接。

## 安全边界

用户提供的视频 URL 只接受 `bilibili.com`、`www.bilibili.com`、`m.bilibili.com` 和 `b23.tv` 的支持形式；短链重定向也受域名约束。账户 Cookie 仅发送至 B 站域名，不发送给媒体 CDN。网络请求必须使用 HTTPS；账户 POST 的跨站重定向被阻止。

Windows 登录信息以当前用户 DPAPI 保护。任务记录不保存 SESSDATA，日志会隐藏常见账号令牌。HTTPS 使用系统证书与 certifi，并保留主机名和证书链校验。

源码版的 FFmpeg 默认只检查 PATH 中的绝对目录；可以在设置中指定可执行文件。打包程序只检查自身资源中的固定路径，不扫描磁盘。
