## 验证方式

- `unittest`：源代码逻辑、真实 Tk 控件、模拟 HTTP 重定向与 Cookie 边界、账号刷新并发、下载恢复和文件合并。
- Ruff：导入整理、基本缺陷检查与一致格式。
- `pip-audit`：Python 运行依赖的公开漏洞公告；结果快照见 `dependency-audit.json`。扫描不会覆盖 FFmpeg 内部或 Windows 系统库。
- 便携烟测：仅复制 exe 到含中文和空格的空目录，清除 Python 环境变量、限制 PATH，确认窗口、运行 DLL、内置 FFmpeg 合并与临时资源正常清理。
- Git 检查：检查忽略规则和已跟踪历史中常见令牌、私钥模式；环境、FFmpeg、账号文件、日志、视频和构建输出不推送。

## 产品取舍与后续计划

1. 目前重试从头下载。真正的断点续传需要校验签名地址、Range 响应和已下载文件身份，再设计暂停与恢复交互。
2. 取消会立即停止后续写入与合并；已经阻塞的网络读取仍需等待当前请求返回或超时，不能承诺所有网络情况下瞬时退出。
3. 目前不支持自动合并多段 MP4、DRM 和平台未授权的媒体。画质以实际返回及队列显示为准。
4. Tk 动画通过事件循环调度，目标帧间隔 16 ms；实测界面和回归测试不等同于所有硬件都能保证 60 FPS。
5. Python 依赖公告检查纳入 CI；FFmpeg 应继续跟随上游维护，版本及构建配置随 Release 记录。
6. 后续可增加更完整的无障碍焦点提示和批量操作反馈，优先保持下载可靠性与页面响应。

这次审查提供具体修复和可复现的测试依据，未进行独立渗透测试、FFmpeg 原生代码审计或所有 Windows 版本的干净虚拟机兼容验证。
